# M3: The Six Paths — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A player chooses a Calling, levels six Paths at hexagon-based rates by hitting training posts and defeating players, and fights with 4 equipped abilities out of 18 plus the Strike.

**Architecture:** As in M1 and M2: every rule is a pure Luau module in `src/shared/Rules`, unit-tested with Lune; thin server services own state and validate every request; the client renders and sends requests. Abilities are catalog data built from six effect kinds (`melee`, `shot`, `dash`, `zone`, `self`, `burst`); a pure planner turns a cast into hits, moves and zones, and one server executor carries the plan out through a single damage pipeline shared with the Strike.

**Tech Stack:** Luau (`--!strict`), Rojo 7.7.1, Lune 0.11.1, StyLua 2.6.0 (Luau build), Selene 0.31.0, ProfileStore 1.0.3 (vendored), plain Roblox UI instances.

**Spec:** `docs/superpowers/specs/2026-11-10-isle-of-avarice-design.md` revision 5 — sections 3.5 (Strike, protections), 4.1–4.4 (all of the Six Paths). Not in this plan: parties (M6), creatures and trials (M4), Coin earning (M4), a guided tutorial.

## Global Constraints

- **Original content only.** No names, characters, abilities or places from any existing work. Path names are Fang, Gale, Ember, Mire, Mend, Bulwark; ability names are exactly those in spec 4.4.
- **Tone:** cartoon knock-outs; "defeated", never "killed"; no blood or gore effects.
- Every file under `src/` except `src/server/Vendor` starts with `--!strict`. Files under `src/shared/` use no Roblox APIs and require each other only by relative string.
- Rule functions never mutate their arguments; they return new values. Exception: `RateLimiter.allow`.
- The server decides everything. A client request names a slot, an ability id or a Path id; the server works out targets, positions, damage, movement and results itself. No client-supplied position, target, damage or time is trusted.
- In server handlers, no yielding call between reading state and committing it.
- Player damage only through `CombatService.damage` (Task 8), which ends in `Humanoid:TakeDamage`. Heals set `Humanoid.Health` directly, capped at `MaxHealth`.
- Saved data contains only strings, numbers, booleans and tables with all-string keys or gap-free arrays. RemoteEvent payloads likewise.
- Numbers fixed by the spec: levels 1–20; level L→L+1 costs `100 × L`; total 19,000 at level 20; first Calling starts at level 3 (300 XP); unlocks at levels 3, 10, 18; rates 1.0 / 0.8 / 0.6 / 0.4 by hexagon distance 0 / 1 / 2 / 3; gained XP = `floor(base × rate)`; post hit base 10, at most once per 0.5 s per post per player; player defeat base 150 to the Calling, only when a blind claim opens; Calling change: first free, then 500 Coin, 7-day cooldown (604,800 s, real time); 4 loadout slots; 0.3 s gap after any ability; every ability value exactly as in spec 4.4.
- Hexagon order (clockwise from the top): Fang, Gale, Ember, Mire, Mend, Bulwark. Opposites: Fang–Mire, Gale–Mend, Ember–Bulwark.
- Allies: every support rule takes an ally list. In M3 the server always passes `{ caster }`.
- `bash scripts/check.sh` must pass before every commit (it formats and lints `src`, `tests` and `playtest`).
- Work happens on branch `feat/m3-paths` (based on `feat/m2-combat`).

## Review Focus

1. **Hostile requests** — `CastAbility` slot 0, 5, 1.5, NaN, a string, nil; `LoadoutAction` with a bad slot, an unknown or 17-character id, a locked ability; `PickCalling` with an unknown Path or a second time; `ChangeCalling` to the same Path, during cooldown, without Coin: each refused with a code, nothing changes. Pinned in Tasks 2, 3 and 6.
2. **Corrupt saved Path data** (unknown Calling, negative/NaN/huge XP, locked or unknown or duplicate loadout entries, wrong types, nil): load yields a valid `PathProgress`, never an error. Pinned in Task 2 (`PathProgress.sanitize`).
3. **Abilities obey protections exactly like the Strike.** A shielded, safe-zone or new-shield target takes no damage *and* no status, pull or knockback; a new-shielded caster cannot hurt players but can hit training posts; a damaging hit ends the caster's respawn shield and Marks an aggressor. Pinned by reading in Tasks 8–9 and by the play test in Task 12.
4. **Movement abuse.** Dash, pull and knockback never move a character through a wall or below the ground, and never use a client position. Pinned by reading in Task 9 (raycast clamp) and the play test in Task 12.
5. **Experience farming.** A post pays a player at most once per 0.5 s; defeat XP only when a claim opens (so at most once an hour per victim); nothing is granted without a Calling, or to a player whose data is not loaded. Pinned in Task 2 (`addXp` with no Calling) and by reading in Tasks 7–8.

### Task 2: Path progress rules

**Files:**
- Create: `src/shared/Rules/PathProgress.luau`
- Test: `tests/path_progress.spec.luau`

**Interfaces:**
- Consumes: `Paths.order`, `Paths.isPath`, `Abilities.list`, `Abilities.forPath`, `Types.PathProgress`.
- Produces:
```luau
PathProgress.MAX_LEVEL = 20
PathProgress.CALLING_START_LEVEL = 3
PathProgress.CHANGE_COST = 500
PathProgress.CHANGE_COOLDOWN = 604800
PathProgress.distance(a: PathId, b: PathId): number                 -- 0..3 around the hexagon
PathProgress.learningRate(calling: string, path: string): number    -- 1 / 0.8 / 0.6 / 0.4; 0 when calling is ""
PathProgress.totalXpForLevel(level: number): number                 -- 100 * (level - 1) * level / 2
PathProgress.maxXp(): number                                        -- 19000
PathProgress.levelForXp(xp: number): number                         -- 1..20; bad input -> 1
PathProgress.level(progress: PathProgress, path: string): number
PathProgress.new(): PathProgress
PathProgress.sanitize(raw: any): PathProgress                       -- never errors
PathProgress.unlocked(progress: PathProgress): { string }           -- ability ids, Abilities.list order
PathProgress.chooseCalling(progress: PathProgress, raw: any): (PathProgress?, string, { string })
-- success: new progress, "CALLING_CHOSEN", newly unlocked ids; failure: nil, "BAD_REQUEST" | "CALLING_ALREADY_SET", {}
PathProgress.changeCalling(progress: PathProgress, raw: any, coin: number, now: number): (PathProgress?, string, number)
-- success: new progress, "CALLING_CHANGED", cost paid (0 or 500); failure: nil, code, 0
-- order: BAD_REQUEST (not a PathId), NO_CALLING, CALLING_SAME, CALLING_COOLDOWN, NOT_ENOUGH_COIN
PathProgress.addXp(progress: PathProgress, path: string, base: number): (PathProgress, number, number, { string })
-- returns new progress, XP actually gained, levels gained, newly unlocked ids
```
- `chooseCalling` sets the Calling and raises that Path's XP to at least `totalXpForLevel(3)` (300). `changeCalling` never touches XP; it increments `callingChanges` and sets `callingChangedAt = now`. The first change (`callingChanges == 0`) is free; the cooldown applies when `callingChangedAt > 0` and `now - callingChangedAt < CHANGE_COOLDOWN`.
- `addXp`: gained = `floor(base * learningRate(calling, path))`, never negative, and XP is capped at `maxXp()`. Unknown path, non-finite or negative base, or no Calling → gained 0 and the same progress.
- `sanitize`: non-table → `new()`. Unknown or non-string `calling` → `""`. `xp` gets exactly the six Path keys; each value a finite number clamped to `0..maxXp()`, otherwise 0. `loadout` is exactly 4 strings: an entry is kept only if it is a string id of an ability the sanitised progress has unlocked and not already earlier in the loadout, otherwise `""`. `callingChanges` and `callingChangedAt` become 0 unless finite and ≥ 0.

### Task 3: Loadout rules and the Paths display data

**Files:**
- Create: `src/shared/Rules/Loadout.luau`, `src/shared/Rules/PathView.luau`
- Test: `tests/loadout.spec.luau`, `tests/path_view.spec.luau`

**Interfaces:**
- Consumes: `PathProgress.*` (Task 2), `Abilities.*`, `Paths.*`.
- Produces:
```luau
Loadout.SLOTS = 4
-- request: { slot = number, abilityId = string }  ("" clears the slot)
Loadout.apply(progress: PathProgress?, raw: any, inSafeZone: boolean): (PathProgress?, string)
-- success: new progress, "LOADOUT_CHANGED"
-- failure order: DATA_NOT_LOADED (nil progress), BAD_REQUEST (shape: non-table, slot not an integer 1..4,
--   abilityId not a string or longer than 16, abilityId not "" and unknown), NO_CALLING, LOADOUT_SAFE_ZONE, NOT_UNLOCKED
-- equipping an id already in another slot moves it there (its old slot becomes "")
Loadout.autoFill(progress: PathProgress, ids: { string }): PathProgress   -- each id not yet equipped goes into the first "" slot, if any

export type AbilityView = { id: string, name: string, description: string, unlockLevel: number, unlocked: boolean, equippedSlot: number }
export type RowView = { path: string, name: string, style: string, level: number, xpText: string, rateText: string, isCalling: boolean, abilities: { AbilityView }, changeText: string, canChange: boolean }
export type SlotView = { slot: number, abilityId: string, name: string }
export type View = { needsCalling: boolean, callingText: string, rows: { RowView }, slots: { SlotView } }
PathView.build(progress: PathProgress, coin: number, now: number): View
```
- `xpText`: `"<xp into level> / <XP for next level>"`, or `"MAX"` at level 20. `rateText`: `"100%"`, `"80%"`, `"60%"`, `"40%"`, or `"—"` without a Calling. `callingText`: `"Calling: <name>"` or `"Choose your Calling"`. `changeText` (per row): `""` on the Calling's own row or without a Calling; otherwise `"Free"` (first change), `"500 Coin"`, or `"Available in N days"` (N = days left, rounded up). `canChange` is true only for `"Free"`, or for `"500 Coin"` when `coin >= 500`. `SlotView.name` is `""` for an empty slot.

- **`damage`, in order:** both players present and the victim alive, else false.
