# M6: Parties — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Up to four players group into a session-only party: they cannot hurt each other by any means, Siphon's heal, Ward and Renewal reach members within 15 studs, support counts as helping against creatures, and the claim and Mark rules stop a party from gaming fights; a party panel, an invite banner and ally markers show it.

**Architecture:** As in M1–M5. Every rule is a pure Luau module in `src/shared/Rules`, unit-tested with Lune; thin server services own state and check every request; the client renders view data and sends requests. Party state lives in `PartyService` as a pure `Party.State`; `Fighters` gets one injected seam, `Fighters.setAllies`, so `Fighters.mayFight` (and with it the Strike, every ability, zones, burns and reflects) refuses allies without `Fighters` requiring any service. Support reach is a pure rule (`Party.reach`) applied by `AbilityService`; creature credit for support is a pure rule (`Rewards.assist`) applied by `CreatureService`.

**Tech Stack:** Luau (`--!strict`), Rojo 7.7.1, Lune 0.11.1, StyLua 2.6.0 (Luau build), Selene 0.31.0, ProfileStore 1.0.3 (vendored), plain Roblox UI instances.

**Spec:** `docs/superpowers/specs/2026-11-10-isle-of-avarice-design.md` revision 8 — section 3.14 (all M6 values and rulings), with 3.5 (protections), 3.9 (creature rewards), 3.10 (trials), 3.13 (Edicts, trading) and 4.3–4.4 (support reaches allies; Siphon gains a 15-stud reach).

**Branch:** `feat/m6-parties`, based on `feat/m5-edicts` after M5's last commit.

## Global Constraints

- Original content only. Tone as before: "defeated", never "killed". The words players see are "Party", "Remove", "Make leader", "Leave".
- Every file under `src/` except `src/server/Vendor` starts with `--!strict`. Files under `src/shared/` use no Roblox APIs and require each other only by relative string. Rule functions never mutate their arguments (exception: `RateLimiter.allow`).
- The server decides everything. A request names at most a user id; the server checks who, where, when and whether they may. No yielding call between reading party state and writing it back.
- **Fighter ids:** a player is their `UserId` (Studio test players are −1 and −2). Never infer a kind from the sign: ask `Fighters.get(id).kind`. Party member ids are always player UserIds.
- **All damage goes through `CombatService.damage(attackerId, targetId, amount, opts)`**, which refuses any pair `Fighters.mayFight` refuses. No other code checks party membership for damage.
- RemoteEvents are created with `LedgerService.makeRemote(name)` and named in `src/shared/Net.luau`; message codes live in `src/shared/Catalog/Messages.luau`.
- Parties are session state: nothing is saved, `schemaVersion` stays 1.
- **Spec 3.14 values:** party size 4 (`Party.MAX_SIZE`); invite = the nearest other player within 15 studs (`Trade.nearest`, the same rule as trading); an invite lasts 20 s (`Party.INVITE_SECONDS`); support reach 15 studs (`allyRadius = 15` on `siphon`, `ward`, `renewal` only); "in a player fight" = Marked, or dealt or took player damage in the last 30 s (`Party.FIGHT_SECONDS`, inclusive below 30, NaN counts as in a fight).
- **Spec 3.14 rulings the code must keep:** only the leader invites, removes and hands over the lead; when the leader leaves, the earliest-joined member leads; a party of one breaks up; a defeat does not end a party, leaving the game does. Only heal, cleanse and shield reach allies; immune, empower, reduction and reflect stay the caster's own. A protected caster (new-player shield, or in the safe zone and not Marked) does not reach an ally in a player fight; support reaching an ally in a player fight ends the caster's respawn shield; support never reaches a player running a duel trial. Support that reaches a creature contributor (hit within 30 s) from outside Tallyport makes the caster a contributor; an assist-only contributor gets XP in the support's Path and is served last for capped drops. A defeat is never credited to a party member of the victim. A claim records the one-hour limit for the killer and every member of the killer's party. Fighting back covers the attacker's whole party.
- `bash scripts/check.sh` passes before every commit.

## Review Focus

1. **Friendly fire is fully off, and only between members.** Strike, every ability (melee, shot, dash, burst, zone), burns, zones and reflects between members do nothing and Mark nobody; a burn, zone or taunt from before joining stops at once; a non-member is never protected; creatures are untouched. Pinned in Task 4 (`Fighters.mayFight` and by reading every `Fighters.list` and `CombatService.damage` call site) and the play test (Task 8, M6.4–M6.5).
2. **Support reaches only members, only with support effects, only within 15 studs.** Rebuke, Afterimage and Shield Bash never spread; a non-member is never healed; a protected caster never heals into a player fight; a duellist is never reached; reaching a fighting ally ends the caster's respawn shield. Pinned in Task 1 (`Party.reach`), Task 2 (catalog test: only `siphon`, `ward`, `renewal` carry `allyRadius`), Task 6 (the own/support split) and the play test (M6.6).
3. **Claims and Marks cannot be gamed by joining or leaving.** No claim, XP or combat-log claim on a party member (including a hit landed before joining, and a member who leaves the game: the exit runs after the combat-log credit); the claim limit is recorded for the whole party and survives leaving; fighting back covers the party; Marks are never changed by a party. Pinned in Task 2 (`Combat.creditFor`, `Protection.isAggressor`, `Protection.recordClaims`), Task 4, Task 5 (exit through `DataService.beforeRelease`) and the play test (M6.5).
4. **Hostile party requests** on `PartyRequest`, `PartyReply` and `PartyAction`: spam, a non-boolean reply, an expired invite, wrong kinds, missing, string, NaN, self or non-member user ids, removing or promoting by a non-leader, inviting a player in a party, a full party. Each is refused with a code and nothing changes. Pinned in Task 1 (`Party.*`), Task 5 (handler order) and the play test (M6.1, M6.3).
5. **Creature reward leeching.** Standing near pays nothing; support counts only when it reaches a contributor who hit within the last 30 s, from outside Tallyport; assisters are served after every damage dealer for capped drops; champions take no assists. Pinned in Task 2 (`Rewards.assist`, `Rewards.awards`), Task 6 (`CreatureService.assist`) and the play test (M6.7).

```luau
-- src/shared/Rules/Party.luau
export type Party = { leader: number, members: { number } }   -- members in join order, the leader included
export type State = { Party }                                -- parties in the order they were made
export type Helper = { position: Vec3, protected: boolean }
-- protected: players cannot attack the caster now (new-player shield, or in the safe zone and not Marked)
export type Helped = { id: number, position: Vec3, inFight: boolean, inDuel: boolean }

Party.MAX_SIZE = 4
Party.INVITE_SECONDS = 20
Party.FIGHT_SECONDS = 30

Party.new(): State                                           -- {}
Party.find(state: State, userId: number): Party?             -- a copy of the party userId is in
Party.allies(state: State, userId: number): { number }       -- the other members, join order; {} when not in a party
Party.allied(state: State, a: number, b: number): boolean    -- a ~= b and both in one party
Party.canInvite(state: State, inviterId: number, targetId: number): (boolean, string)
-- order: BAD_REQUEST (inviterId == targetId), PARTY_NOT_LEADER (inviter in a party, not its leader),
-- PARTY_FULL (inviter's party has MAX_SIZE members), PARTY_TARGET_IN_PARTY (target in any party);
-- success: true, "PARTY_INVITE_SENT"
Party.join(state: State, inviterId: number, targetId: number): (State?, string)
-- canInvite again; a solo inviter makes a new party { leader = inviter, members = { inviter, target } }
-- appended to the state; otherwise target is appended to the inviter's members. Success "PARTY_JOINED"
Party.leave(state: State, userId: number): (State?, string)
-- PARTY_NOT_IN; removes userId; a party left with one member is removed from the state; a leader who
-- left is replaced by the first remaining member in join order. Success "PARTY_LEFT"
Party.kick(state: State, leaderId: number, rawTargetId: any): (State?, string)
-- order: PARTY_NOT_IN (leaderId not in a party), PARTY_NOT_LEADER, BAD_REQUEST (rawTargetId not a
-- number, == leaderId, or not a member); then the same removal as leave. Success "PARTY_MEMBER_KICKED"
Party.promote(state: State, leaderId: number, rawTargetId: any): (State?, string)
-- same refusals and order as kick; success sets leader = target, members unchanged, "PARTY_NEW_LEADER"
Party.reach(helper: Helper, allies: { Helped }, radius: number): ({ number }, boolean)
-- ids reached, in input order, and whether any reached ally is in a player fight. An ally is reached
-- when its 3D distance is <= radius (written so NaN positions or radius reach nobody), it is not
-- inDuel, and not (helper.protected and ally.inFight)
Party.inFight(marked: boolean, lastFightAt: number?, now: number): boolean
-- marked, or lastFightAt ~= nil and not (now - lastFightAt >= FIGHT_SECONDS)
```
- Net (names equal keys), with these comments in `Net.luau`:
  - `PartyRequest` — client → server: `()` invite the nearest player
  - `PartyInvite` — server → one client: `(invite: { from: string, seconds: number }?)`, nil withdraws it
  - `PartyReply` — client → server: `(accept: boolean)`
  - `PartyAction` — client → server: `(request: { kind: "leave" } | { kind: "kick", userId: number } | { kind: "promote", userId: number })`
  - `PartySync` — server → one client: `(sync: PartyView.Sync?)`, nil = not in a party

```luau
--!strict
local T = require("./harness")
local Party = require("../src/shared/Rules/Party")

local function copy(value: any): any
	if type(value) ~= "table" then
		return value
	end
	local out = {}
	for k, v in value do
		out[k] = copy(v)
	end
	return out
end

-- A step that must succeed: checks its code and returns the new state.
local function ok(expected: string, state: Party.State?, code: string): Party.State
	T.eq(code, expected)
	T.truthy(state ~= nil, expected)
	return state :: Party.State
end

-- Members 1..n in one party led by 1.
local function partyOf(n: number): Party.State
	local s = Party.new()
	for id = 2, n do
		s = ok("PARTY_JOINED", Party.join(s, 1, id))
	end
	return s
end

local function helped(id: number, x: number, over: { [string]: any }?): Party.Helped
	local h: { [string]: any } =
		{ id = id, position = { x = x, y = 0, z = 0 }, inFight = false, inDuel = false }
	for k, v in over or {} do
		h[k] = v
```

### Task 2: Combat, protection and reward rules for parties; Siphon's reach

**Interfaces:**
- Consumes: `Paths.isPath`, `Paths.order`, existing `Combat.HitLog`, `Protection.ClaimHistory`, `Rewards.Tally`.
- Produces:
```luau
-- Combat: a new optional last parameter
Combat.creditFor(log: HitLog, victimId: number, now: number, windowSeconds: number,
	creatureLog: HitLog?, allies: { number }?): number?
-- unchanged, except nil when the attacker it would credit is in `allies` (the victim's party)

-- Protection: a new optional last parameter, and one new function
Protection.isAggressor(log: HitLog, attackerId: number, victimId: number, victimMarked: boolean,
	now: number, victimAllies: { number }?): boolean
-- also false when the last player to hit the attacker, within RETALIATE_SECONDS, is in victimAllies
Protection.recordClaims(history: ClaimHistory, killerIds: { number }, victimId: number, now: number): ClaimHistory
-- recordClaim for each killer id; never mutates `history`

-- Rewards
export type Tally = { [string]: { lastAt: number, total: number, byPath: { [string]: number }, assist: string? } }
Rewards.assist(tally: Tally, helperId: number, helpedIds: { number }, path: string, now: number): Tally
-- when some id in helpedIds other than helperId has an entry with now - lastAt <= CONTRIBUTOR_SECONDS,
-- the helper's entry becomes { lastAt = now, total = old total or 0, byPath = copy of old byPath or {},
```
