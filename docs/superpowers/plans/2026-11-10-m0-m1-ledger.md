# M0 + M1: Project Skeleton and The Ledger — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Roblox place, built entirely from this repo, where a player walks a greybox island, opens caches to find 12 Relics, claims them into a saved Ledger, and sees a server message when the Ledger is complete.

**Architecture:** All game rules are pure Luau modules in `src/shared/Rules` with no Roblox APIs, unit-tested with Lune outside Roblox. Thin server services own state, validate every client request and persist with ProfileStore. The client only renders state the server sends. Rojo builds the place file.

**Tech Stack:** Luau (`--!strict`), Rojo 7.7.1, Lune 0.11.1, StyLua 2.6.0, Selene 0.31.0, ProfileStore 1.0.3 (vendored), plain Roblox UI instances.

**Spec:** `docs/superpowers/specs/2026-11-10-isle-of-avarice-design.md` (sections 3.1, 3.2, 3.7, 5, 6 apply to this plan; combat, the Vault, the blind claim, Paths, Edicts, trading and scarcity enforcement are later milestones and must NOT be built here).

## Global Constraints

- **Original content only.** No names, characters, cards, abilities or places from *Hunter x Hunter* or any other existing work, in code, data, comments or UI text.
- Fixed names: **Ledger**, **Relics**, **Claimants**, **Tallyport**, **the Hoarder**, **Coin**.
- Every file under `src/` starts with `--!strict`.
- Files under `src/shared/` use no Roblox APIs (`game`, `workspace`, `Instance`, `task`, `script`, Roblox data types) and require each other only by relative string, e.g. `require("./Ledger")`, `require("../Catalog/Relics")`. They must run unchanged under Lune.
- Rule functions never mutate their arguments. They return new values. The one exception is `RateLimiter.allow`, which mutates its bucket.
- The server decides everything. The client never changes Ledger state; it sends requests and renders what the server sends.
- Free slots: **20**. Relics in this plan: **12**, ids `R001`–`R012`, slots 1–12.
- Card ids are strings. Saved data contains only strings, numbers, booleans and tables with either all-string keys or gap-free array keys (a ProfileStore requirement).
- No external runtime dependencies except the vendored ProfileStore. No Wally.
- `scripts/check.sh` must pass before every commit.
- Work happens on branch `feat/m0-m1-ledger`.

## Review Focus

1. **Corrupt or old saved data** (unknown card ids, more than 20 free cards, wrong types, `nil`): loading must produce a valid Ledger, never an error. Pinned in Task 3 (`Ledger.sanitize`).
2. **Hostile client payloads** (non-table, missing fields, index 0, 21, 1.5, NaN, huge strings): rejected with a code, never an error, Ledger unchanged. Pinned in Task 4 (`LedgerActions.apply`).
3. **Two players open one cache at the same instant:** exactly one gets the card. Pinned in Task 4 (`Sources.tryCollect` second call returns `CACHE_EMPTY`), and Task 7 must not yield between check and commit.
4. **Free slots full when opening a cache:** the cache is not consumed and the player is told why. Pinned in Task 4.
5. **Requests before data has loaded, or after the player left:** ignored with `DATA_NOT_LOADED`; nothing is created for a missing profile. Pinned in Task 4 (nil ledger cases); Task 6 and 7 reviewers check the service paths by reading.

### Task 3: Ledger rules

**Files:**
- Create: `src/shared/Rules/Ledger.luau`
- Test: `tests/ledger.spec.luau`

**Interfaces:**
- Consumes: `Types`, `Relics.byId`, `Relics.list`.
- Produces (every function returns a new Ledger and leaves its input untouched; on failure returns `nil` and an error code):
```luau
Ledger.FREE_SLOTS = 20
Ledger.new(): Ledger
Ledger.add(ledger: Ledger, cardId: CardId): (Ledger?, string?)        -- UNKNOWN_CARD, FREE_FULL
Ledger.claim(ledger: Ledger, freeIndex: number): (Ledger?, string?)   -- BAD_INDEX, ALREADY_CLAIMED
Ledger.unclaim(ledger: Ledger, cardId: CardId): (Ledger?, string?)    -- NOT_CLAIMED, FREE_FULL
Ledger.discard(ledger: Ledger, freeIndex: number): (Ledger?, string?) -- BAD_INDEX
Ledger.count(ledger: Ledger, cardId: CardId): number                  -- claimed (0 or 1) + spares
Ledger.claimedCount(ledger: Ledger): number
Ledger.isComplete(ledger: Ledger): boolean                            -- every Relic in the catalog claimed
Ledger.sanitize(raw: any): Ledger                                     -- never errors
```
- `add` appends to the end of `free`. `claim` and `discard` remove the entry and shift later entries down (no gaps). `BAD_INDEX` covers non-integers and anything outside `1..#free`.
- `sanitize`: returns `Ledger.new()` for a non-table. Keeps a `claimed` key only if it is a known Relic id with value `true`. Keeps `free` entries, in order, only if they are known card ids, and at most the first 20.

### Task 4: Request, cache and rate-limit rules

**Files:**
- Create: `src/shared/Rules/LedgerActions.luau`, `src/shared/Rules/Sources.luau`, `src/shared/Rules/RateLimiter.luau`
- Test: `tests/ledger_actions.spec.luau`, `tests/sources.spec.luau`, `tests/rate_limiter.spec.luau`

**Interfaces:**
- Consumes: `Ledger.*` from Task 3, `Tiers.info`, `Relics.byId`, `Types`.
- Produces:
```luau
-- A client request is one of:
--   { kind = "claim", freeIndex = number }
--   { kind = "unclaim", cardId = string }
--   { kind = "discard", freeIndex = number }
LedgerActions.apply(ledger: Ledger?, raw: any): (Ledger?, string, CardId?)
-- success: new ledger, "CLAIMED" | "UNCLAIMED" | "DISCARDED", the card id affected
-- failure: nil, "DATA_NOT_LOADED" | "BAD_REQUEST" | a Ledger error code, nil

export type SourceState = { [string]: number }   -- cache id -> time it becomes available
Sources.MAX_DISTANCE = 15
Sources.new(caches: { Cache }): SourceState      -- every cache available at time 0
Sources.isAvailable(state: SourceState, cacheId: string, now: number): boolean
Sources.tryCollect(state: SourceState, ledger: Ledger?, cache: Cache, now: number, distance: number)
	: (SourceState, Ledger?, string)
-- success: new state, new ledger, "GOT_CARD"
-- failure: the SAME state, nil, "DATA_NOT_LOADED" | "TOO_FAR" | "CACHE_EMPTY" | "FREE_FULL"
-- checked in that order; on success the cache becomes available at now + the Relic tier's cacheRespawnSeconds

export type Bucket = { tokens: number, last: number }
RateLimiter.new(capacity: number, now: number): Bucket
RateLimiter.allow(bucket: Bucket, now: number, capacity: number, refillPerSecond: number): boolean
```
- `LedgerActions.apply` returns `BAD_REQUEST` for: non-table `raw`, unknown `kind`, a `freeIndex` that is not a number, a `cardId` that is not a string or is longer than 16 characters. Ledger error codes pass through unchanged.
- An unknown cache id (not in the state) is `CACHE_EMPTY`.
